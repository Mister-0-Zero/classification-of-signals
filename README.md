# classificationSignal

Классификация радиосигналов по реальным спектральным измерениям анализатора
Rohde & Schwarz R&S FSL3. Проект развивается из практической части курсовой
работы в исследование для ВКР.

Основная задача — предварительное различение АМ, ЧМ и шумовой обстановки
для поддержки оператора радиоконтроля. Исторические результаты получены
на небольшом исходном наборе. Новые измерения собраны, но требуют проверки
качества и повторной оценки моделей.

│   ├── FM_dop/                 # Дополнительные смещённые/частичные FM-фрагменты
│   └── old/                    # Предыдущая серия и сомнительные записи

│   ├── 2026_ОПФиСТС_КП_ИБ-31_Лядков_АС.docx

Служебные папки скрыты в Проводнике и дереве VS Code:

- `.venv/` — существующее окружение Python. Путь сохранён, поскольку перенос
  Windows-окружения может нарушить работу установленных команд и активации.
- `.local/archive/legacy/` — прежняя папка `всякое` без документов,
  перенесённых в `docs/references/`.
- `.local/archive/baseline/` — прежняя вспомогательная папка `baseline`.
- `.local/cache/` — кэши, перенесённые при уборке. Python может создавать новые
  `__pycache__`; они исключены из Git и скрыты в VS Code.
- `.vscode/settings.json` — настройки отображения и путь к окружению.

Сбор и обучение запускаются из корня проекта, если ниже не указано другое.

## Окружение

Рекомендуется Python 3.11+. Для существующего окружения:

```powershell
.\.venv\Scripts\Activate.ps1
python -m pip install -r requirements.txt
```

При создании окружения с нуля сначала выполните:

```powershell
python -m venv .venv
```

В зависимостях используется пакет `torch`. GPU используется моделями CNN,
если установленная сборка PyTorch поддерживает доступную CUDA; возможна работа на CPU.

Инвентаризация на 22.10.2026 по папкам запусков с `run_config.json`:

| Каталог | Папки верхнего уровня внутри класса | Записи измерений |
|---|---:|---:|
| `data/AM` | 9 | 54 |
| `data/FM` | 36 | 108 |
| `data/Noise` | 10 | 66 |
| `data/FM_dop` | 1 | 108 |

Число папок не является оценкой числа независимых источников: для `FM_dop`
внутренняя структура отличается от основных классов. Количество запусков
также не означает количество независимых обучающих примеров.

AM и FM записаны с профилями `baseline`, `high_resolution` и `smoothed`.
В новых Noise и дополнительных FM есть полосы обзора 180, 250 и 400 кГц.
Поэтому одинаковое число частотных точек ещё не означает одинаковый частотный масштаб.

Новые данные пока не признаны очищенным обучающим набором. Существующие
загрузчики ориентированы на `AM`, `FM`, `Noise` и прежний список исключений:
`Noise_101_9`, `FM_88_3`, `FM_95_2`. Они не включают `FM_dop` или `old`
автоматически. Применимость старых исключений к новым записям следует проверить.
В скрипте сбора есть режим PM, но наличие режима не означает наличие собранного класса.

## Формат измерений

Для обычных измерений используется структура:

```text
data/<class>/<sample_group_name>/<run_id>/
├── samples/*.csv
├── metadata.csv
└── run_config.json
```

Основные столбцы CSV:

```csv
sample_id,class_name,sample_group_name,sweep_idx,point_idx,frequency_hz,amplitude_dbm
```

`sweep_idx` — номер временного среза, `point_idx` — частотная точка,
`frequency_hz` — частота в Гц, `amplitude_dbm` — записанная амплитуда.
Параметры прибора и генератора находятся в метаданных и конфигурации запуска.

## Сбор данных

Интерактивный запуск:

```powershell
python get_data.py
```

Скрипт поддерживает режимы `fm`, `am`, `noise`, `fm_dop` и `pm`.
Предварительный просмотр плана без подключения к прибору:

```powershell
python get_data.py --mode fm --dry-run
python get_data.py --mode am --dry-run
python get_data.py --mode noise --dry-run
python get_data.py --mode fm_dop --dry-run
python get_data.py --mode pm --dry-run
```

Все параметры запуска:

```powershell
python get_data.py --help
```

По умолчанию данные сохраняются в `data/`. Успешно собранные комбинации
при повторном запуске пропускаются; `--force` разрешает повторный сбор.
AM и PM требуют ручной настройки генератора с подтверждением готовности.

## Подготовка и модели

В прежних экспериментах использовались три представления:

- статистические и структурные признаки спектральной трассы;
- усреднённый по пяти срезам вектор из 501 амплитуды;
- матрица пяти последовательных срезов `5 × 501` для 2D CNN.

Частота переводится в относительную шкалу. Масштабирование для линейных
моделей и нейросетей рассчитывается на обучающей части. Для 2D CNN
предусмотрены сдвиги, маскирование краёв спектра и добавление небольшого шума.

Скрипты запускаются из корня с указанием папки `scripts`:

```powershell
python scripts/baseline_logreg.py
python scripts/mlp_spectrum.py
python scripts/cnn_spectrum.py
python scripts/cnn2d_spectrum.py
```

Групповая кросс-валидация:

```powershell
python scripts/cross_validate_models.py --skip-cnn --output-dir results/new_data_baseline
python scripts/cross_validate_models.py --output-dir results/new_data_full
```

Это команды существующего конвейера. Перед обучением на новых данных
требуется проверить качество записей, совместимость представлений и группировку.
Явный `--output-dir` сохраняет прежние результаты от перезаписи.

Ноутбук находится в `scripts/research.ipynb`. Для его локальных импортов
рабочая папка ядра должна быть `scripts/`, либо эта папка должна быть доступна
в `sys.path`. Загрузчик определяет корень `data/` относительно своего файла.

## Прежний эксперимент и результаты

Отчёт в `docs/` и CSV в `results/cross_validation/` описывают прежний
набор из 14 исходных измерений: 4 AM, 6 FM и 4 Noise. Каждое измерение
содержало 50 срезов по 501 точке. Неперекрывающиеся окна по 5 срезов дали
140 объектов: 40 AM, 60 FM, 40 Noise. Предыдущая серия хранится в `data/old/`.

Прежние параметры анализатора: span 250 кГц, RBW/VBW 10 кГц,
детектор POS, режим трассы WRIT. AM формировались генератором SMB100A,
FM принимались из эфира, Noise регистрировались на участках без выраженного сигнала.

Оценка использовала `StratifiedGroupKFold`, 4 фолда и группировку
по `sample_group_name`. Для CNN эпоха выбиралась на внутреннем групповом
разделении обучающей части. Разные профили и связанные записи одного
источника должны оставаться в одной группе.

| Модель | Представление | OOF accuracy | OOF macro F1 |
|---|---|---:|---:|
| Random Forest | Вычисляемые признаки | 0.8643 | 0.8634 |
| Gradient Boosting | Вычисляемые признаки | 0.8143 | 0.8171 |
| Logistic Regression | Вычисляемые признаки | 0.7643 | 0.7773 |
| 2D CNN | Матрица `5 × 501` | 0.7571 | 0.7657 |
| MLP | Усреднённый вектор | 0.6929 | 0.7084 |
| Logistic Regression | Усреднённый вектор | 0.6786 | 0.6960 |
| MLP | Вычисляемые признаки | 0.5714 | 0.5790 |

Эти показатели не являются оценкой новых данных. Результаты фиксированного
разбиения из ноутбука также не заменяют групповую кросс-валидацию.

Итоговые CSV каждого запуска: `summary.csv`, `fold_metrics.csv`, `predictions.csv`.
Каталоги `cross_validation_no_cnn` и `cross_validation_smoke` сохранены отдельно.

## Desktop приложение SignalScope

В `desktop/` добавлено приложение для сканирования и сбора данных в режиме
имитации. Реальное подключение к анализатору и модели в этой версии отключены.
Данные имитации сохраняются отдельно от исследовательского `data/`.

Запуск из исходников в отдельном окружении:

```powershell
python -m venv .local/desktop_env
.local/desktop_env/Scripts/python.exe -m pip install -r desktop/requirements.txt
.local/desktop_env/Scripts/python.exe desktop/run.py
```

Готовая portable Windows-сборка работает без установленного Python.
Описание функций, формата данных, проверок и сборки: `desktop/README.md`.
