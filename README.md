# classificationSignal

Проект для классификации радиосигналов по реальным спектральным измерениям, полученным с анализатора спектра.

Задача проекта — выполнить первичную автоматизированную классификацию спектрального фрагмента на один из трех классов:

- `AM` — амплитудно-модулированный сигнал;
- `FM` — частотно-модулированный сигнал;
- `Noise` — шумовая обстановка.

Проект используется как практическая часть курсовой работы. В нем реализованы загрузка экспериментальных спектральных данных, разведочный анализ, предварительная обработка, формирование объектов классификации и сравнение моделей машинного обучения.

## Кратко

Основной рабочий сценарий:

1. Загрузить реальные спектральные измерения из `data/`.
2. Исключить сомнительные записи, не входящие в финальный рабочий набор.
3. Перейти от абсолютной частоты к относительной частотной оси.
4. Сформировать объекты классификации из окон по `5` последовательным временным срезам.
5. Подготовить разные входные представления данных:
   - вычисляемые статистические и спектральные признаки;
   - усредненный вектор амплитуд из `501` точки;
   - матрицу `5 x 501` для 2D CNN.
6. Сравнить модели классификации методом групповой кросс-валидации.
7. Оценить качество по `accuracy`, `macro F1-score`, `classification_report` и `confusion_matrix`.

## Данные

Данные расположены в `data/` и разложены по классам:

```text
data/
├── AM/
├── FM/
├── Noise/
└── somnitelno/
```

Каждый исходный набор соответствует одному измерению на заданной центральной частоте. Внутри набора находится папка запуска вида `YYYYMMDD_HHMMSS`, в которой лежат:

- `samples/*.csv` — спектральные точки;
- `metadata.csv` — метаданные измерения;
- `run_config.json` — параметры настройки анализатора спектра.

Формат CSV с измерениями:

```csv
sample_id,class_name,sample_group_name,sweep_idx,point_idx,frequency_hz,amplitude_dbm
AM_102_3_20260514_124354_0000,AM,AM_102_3,0,0,102175000.000,-8.066872
```

Основные поля:

- `sample_id` — идентификатор записи;
- `class_name` — класс сигнала: `AM`, `FM`, `Noise`;
- `sample_group_name` — имя исходного набора измерений, например `AM_102_3`;
- `sweep_idx` — номер временного среза;
- `point_idx` — номер частотной точки внутри временного среза;
- `frequency_hz` — частота точки в Гц;
- `amplitude_dbm` — амплитуда в dBm.

В коде используется исходное название поля `sweep_idx`, но в отчете этот объект описывается как номер временного среза.

## Рабочий набор данных

По умолчанию используется очищенный рабочий набор. В `mainFunction.py` задан список исключений:

```python
DEFAULT_EXCLUDED_GROUPS = frozenset({"Noise_101_9", "FM_88_3", "FM_95_2"})
```

Причины исключения:

- `Noise_101_9` визуально содержит выраженную структуру, близкую к FM, поэтому плохо выполняет роль фонового шума;
- `FM_88_3` и `FM_95_2` были помечены как сомнительные FM-измерения, так как визуально ближе к шуму;
- `somnitelno/` не входит в основной набор и загрузчиками игнорируется.

Финальный рабочий набор:

- `AM`: `AM_102_3`, `AM_104_45`, `AM_94_6`, `AM_94_61`;
- `FM`: `FM_101_8`, `FM_104_7`, `FM_87_5`, `FM_87_9`, `FM_94`, `FM_94_4`;
- `Noise`: `Noise_104_4`, `Noise_113_9`, `Noise_87_7`, `Noise_93_4`.

Итого используется `14` исходных наборов измерений:

- `4` AM;
- `6` FM;
- `4` Noise.

Каждый исходный набор содержит:

- `50` временных срезов;
- `501` частотную точку на временной срез;
- `50 x 501 = 25 050` измерений амплитуды.

Общий объем рабочего набора:

```text
14 x 50 x 501 = 350 700 строк измерений
```

При формировании объектов классификации используется окно из `5` последовательных временных срезов. При неперекрывающейся нарезке это дает:

```text
14 x (50 / 5) = 140 объектов классификации
```

Распределение объектов:

- `AM`: `40`;
- `FM`: `60`;
- `Noise`: `40`.

## Параметры измерений

Основные параметры регистрации спектров:

- анализатор спектра: `Rohde & Schwarz FSL-3`;
- диапазон центральных частот рабочих измерений: примерно `87,5-113,9 МГц`;
- ширина обзора `span`: `250 кГц`;
- `RBW`: `10 кГц`;
- `VBW`: `10 кГц`;
- число точек на временной срез: `501`;
- число временных срезов на измерение: `50`;
- detector: `POS`;
- trace mode: `WRIT`;
- задержка между временными срезами: `0,05 с`;
- пауза после конфигурации: `1 с`.

В признаки для обучения не включаются сведения о приборе, адресе прибора или служебные метаданные. Используются только частотная ось, амплитуда, номер временного среза и производные признаки.

## Сбор новых данных

Скрипт `get_data.py` поддерживает два интерактивных режима:

- `FM` — автоматический проход по списку из 36 радиостанций;
- `AM` — пошаговый сбор с ручной установкой параметров генератора.

Обычный интерактивный запуск:

```powershell
python get_data.py
```

Предварительный просмотр плана без подключения к анализатору:

```powershell
python get_data.py --mode fm --profiles baseline high_resolution smoothed --dry-run
python get_data.py --mode am --profiles baseline high_resolution smoothed --dry-run
```

Прямой запуск заданного режима:

```powershell
python get_data.py --mode fm
python get_data.py --mode am
```

По умолчанию используются три профиля анализатора:

- `baseline`: span `250 кГц`, RBW/VBW `10 кГц`;
- `high_resolution`: span `250 кГц`, RBW/VBW `3 кГц`;
- `smoothed`: span `250 кГц`, RBW `10 кГц`, VBW `3 кГц`.

План AM включает 18 ручных установок генератора: по две комбинации параметров для девяти несущих частот. Используются уровни `-40`, `-30` и `-20 дБм`, глубины модуляции `20`, `50` и `80 %`, а также частоты модуляции `20`, `50` и `80 кГц`. Для каждой установки автоматически регистрируются все выбранные профили анализатора.

Для AM скрипт выводит частоту несущей, уровень, глубину и частоту модуляции. После установки генератора нужно нажать Enter или ввести `готов`. Команды `s` и `q` позволяют пропустить установку или завершить серию.

Успешно собранные комбинации при повторном запуске пропускаются. Для принудительного повторного сбора используется флаг `--force`. Ошибки отдельных измерений записываются в `data/collection_failures.jsonl`, после чего серия продолжается.

Настройка анализатора сохраняется в `run_config.json`, а в `metadata.csv` дополнительно записываются профиль анализатора, название источника и параметры AM-генератора. Все измерения сохраняются в `data/`.

Важно: разные профили одной станции или несущей должны оставаться в одной группе при кросс-валидации. Для обучения трехклассовой модели данные класса `Noise` также следует собирать с теми же профилями анализатора.

## Формирование объектов классификации

Базовая единица исходных данных — один временной срез из `501` частотной точки. Для обучения используется окно из нескольких последовательных срезов.

Пример формирования объектов:

```python
from mainFunction import load_all_dataset, make_sweep_examples

df = load_all_dataset()
X, y, meta = make_sweep_examples(
    df,
    window_size=5,
    aggregate="mean",
)

print(X.shape)
print(y[:5])
print(meta.head())
```

Режимы агрегации:

- `aggregate="mean"` — усреднить амплитуды по временным срезам внутри окна;
- `aggregate="median"` — взять медиану по временным срезам;
- `aggregate="none"` — сохранить все временные срезы внутри окна, используется для CNN.

Размерности:

- `window_size=5`, `aggregate="mean"`: `501` признак на объект;
- `window_size=5`, `aggregate="none"`: `5 x 501` значений на объект.

## Предварительная обработка

Основные операции:

1. Переход к относительной частоте:

```text
relative_frequency_hz = frequency_hz - center_frequency_hz
```

Это снижает риск того, что модель будет опираться на абсолютную центральную частоту вместо формы спектра.

2. Формирование окон из последовательных временных срезов.

Один временной срез может быть шумным и нестабильным. Окно из `5` срезов выбрано как компромисс между устойчивостью признаков и числом обучающих объектов.

3. Масштабирование данных.

Масштабирование используется там, где оно требуется модели:

- `Logistic Regression` и `MLP` используют стандартизацию;
- `Random Forest` и `Gradient Boosting` обучаются на вычисляемых признаках без обязательной стандартизации;
- `2D CNN` нормализует матрицы амплитуд по параметрам, рассчитанным только на обучающей части.

## Модели

В проекте реализованы несколько групп моделей.

Модели на вычисляемых признаках:

- `Logistic Regression`;

- `MLPClassifier`.

Модели на спектральных представлениях:

Финальная оценка моделей выполняется в `cross_validate_models.py`.

## Групповая кросс-валидация

Для честной оценки используется `StratifiedGroupKFold` с группировкой по `sample_group_name`.

Причина: объекты, полученные из одного исходного набора измерений, похожи между собой. Если случайно перемешать окна и разделить их на train/test, часть почти одинаковых объектов может попасть и в обучение, и в проверку. Это приведет к утечке данных и завышенным метрикам.

Параметры финальной оценки:

- метод: стратифицированная групповая кросс-валидация;
- число фолдов: `4`;
- группировка: `sample_group_name`;
- размер объекта: `5` последовательных временных срезов;
- число объектов: `140`;
- ключевая метрика: `macro F1-score`.

Запуск финальной оценки без CNN:

```powershell
python cross_validate_models.py --skip-cnn
```

Запуск полной оценки, включая 2D CNN:

```powershell
python cross_validate_models.py
```

Для сокращения времени обучения CNN можно изменить параметры:

```powershell
python cross_validate_models.py --cnn-epochs 150 --cnn-patience 40
```

Результаты сохраняются в:

```text
results/cross_validation/
├── summary.csv
├── fold_metrics.csv
└── predictions.csv
```

## Основные проектные решения

### Почему используется относительная частота

Абсолютная центральная частота может стать нежелательной подсказкой для модели. Поэтому частотная ось переводится в относительную шкалу. Так модель сильнее ориентируется на форму спектра, а не на то, где именно был записан фрагмент.

### Почему используется окно из 5 временных срезов

Один временной срез может быть нестабильным. Усреднение нескольких срезов снижает случайные колебания амплитуды и делает форму спектра устойчивее. Слишком большое окно уменьшает число обучающих объектов. Поэтому `5` срезов выбраны как рабочий компромисс.

### Почему оценка делается по группам

Окна из одного исходного набора измерений сильно связаны между собой. Случайное перемешивание отдельных окон создает утечку данных. Групповая кросс-валидация проверяет модель на целых исходных наборах, которые не попадали в обучение.

### Почему сравниваются разные модели

Классические модели показывают, насколько информативны вручную построенные признаки. Нейросетевые модели проверяют возможность учить форму спектра напрямую. Это позволяет сравнить два подхода:

- классификацию по инженерным признакам;
- классификацию по форме спектрального представления.

## Текущий вывод

Для текущего объема данных наиболее надежным вариантом является `Random Forest` на вычисляемых признаках. Модель показала лучший результат в групповой кросс-валидации и хорошо подходит как сильный baseline для малой выборки.

`2D CNN` подтверждает, что форма спектра может использоваться напрямую, но при текущем числе объектов нейросетевая модель менее устойчива, чем Random Forest. Для дальнейшего улучшения CNN требуется расширение набора реальных измерений и проверка на большем числе классов и условий регистрации.

Проект можно развивать в сторону программного модуля, который получает спектральные данные от анализатора, выполняет предварительную классификацию и передает результат оператору для проверки.
