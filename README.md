# classificationSignal

Проект для классификации радиосигналов по экспериментальным спектральным измерениям.
Цель: автоматически определить тип участка спектра по данным анализатора спектра:

- `AM` — амплитудная модуляция;
- `FM` — частотная модуляция;
- `Noise` — фоновый шум.

Проект используется как практическая часть курсовой работы: данные собраны с реального анализатора спектра, затем по ним выполняются EDA, подготовка признаков и обучение моделей машинного обучения.

## Кратко

Основной рабочий сценарий:

1. Загрузить реальные спектральные датасеты из `data/`.
2. Перейти от абсолютной частоты к относительной частоте относительно центра измерения.
3. Сформировать обучающие объекты из окон по `5` последовательных sweep.
4. Построить статистические, shape- и спектральные признаки.
5. Обучить и сравнить модели:
   - `Logistic Regression`;
   - `Random Forest`;
   - `Gradient Boosting`;
   - `MLP`;
   - `1D CNN`;
   - `2D CNN`.
6. Оценить качество через `accuracy`, `macro avg F1-score`, `classification_report` и `confusion_matrix`.

## Данные

Данные находятся в папке `data/` и разложены по классам:

```text
data/
├── AM/
├── FM/
├── Noise/
└── somnitelno/
```

Каждый датасет соответствует одному измерению на заданной центральной частоте. Внутри каждого датасета находится папка запуска вида `YYYYMMDD_HHMMSS`, в которой лежат:

- `samples/*.csv` — спектральные точки;
- `metadata.csv` — метаданные измерения;
- `run_config.json` — параметры настройки анализатора спектра.

Формат CSV с измерениями:

```csv
sample_id,class_name,sample_group_name,sweep_idx,point_idx,frequency_hz,amplitude_dbm
AM_102_3_20260514_124354_0000,AM,AM_102_3,0,0,102175000.000,-8.066872
```

Основные поля:

- `sample_id` — идентификатор записи;
- `class_name` — класс сигнала: `AM`, `FM`, `Noise`;
- `sample_group_name` — имя датасета, например `AM_102_3`;
- `sweep_idx` — номер временного sweep;
- `point_idx` — номер точки внутри sweep;
- `frequency_hz` — частота точки в Гц;
- `amplitude_dbm` — амплитуда в dBm.

## Рабочий набор данных

По умолчанию проект использует очищенный рабочий набор. В `mainFunction.py` задано:

```python
DEFAULT_EXCLUDED_GROUPS = frozenset({"Noise_101_9", "FM_88_3", "FM_95_2"})
```

Причина исключения:

- `Noise_101_9` визуально содержит выраженную структуру, близкую к FM, поэтому плохо выполняет роль фонового шума;
- `FM_88_3` и `FM_95_2` были помечены как сомнительные FM-измерения, так как визуально ближе к шуму;
- `somnitelno/` не входит в основной набор и загрузчиками игнорируется.

Актуальный рабочий набор:

- `AM`: `AM_102_3`, `AM_104_45`, `AM_94_6`, `AM_94_61`;
- `FM`: `FM_101_8`, `FM_104_7`, `FM_87_5`, `FM_87_9`, `FM_94`, `FM_94_4`;
- `Noise`: `Noise_104_4`, `Noise_113_9`, `Noise_87_7`, `Noise_93_4`.

Итого используется `14` исходных датасетов:

- `4` AM;
- `6` FM;
- `4` Noise.

Каждый исходный датасет содержит:

- `50` временных sweep;
- `501` частотную точку на sweep;
- `50 × 501 = 25 050` измерений амплитуды.

Общий объем рабочего набора:

```text
14 × 50 × 501 = 350 700 строк измерений
```

## Параметры измерений

Основные параметры регистрации спектров:

- анализатор спектра: `Rohde & Schwarz FSL-3`;
- диапазон центральных частот: примерно `87,5–113,9 МГц`;
- ширина обзора `span`: `250 кГц`;
- `RBW`: `10 кГц`;
- `VBW`: `10 кГц`;
- число точек sweep: `501`;
- число sweep на измерение: `50`;
- детектор: `POS`;
- trace mode: `WRIT`;
- задержка между sweep: `0,05 с`;
- пауза после конфигурации: `1 с`.

В обучающие признаки не включается информация о приборе, адресе прибора или служебные метаданные. Используются только частотная ось, амплитуда, индекс sweep и производные признаки.

## Формирование объектов классификации

Базовая единица исходных данных — один sweep из `501` точки. Для обучения используется окно из нескольких sweep.

По умолчанию:

```python
WINDOW_SIZE = 5
```

Это означает, что один обучающий объект строится по `5` последовательным временным sweep.

Формирование примеров:

```python
from mainFunction import load_all_dataset, make_sweep_examples

df = load_all_dataset()
X, y, meta = make_sweep_examples(
    df,
    window_size=5,
    aggregate="mean",
)

print(X.shape)
print(y[:5])
print(meta.head())
```

Режимы агрегации:

- `aggregate="mean"` — усреднить амплитуды по sweep внутри окна;
- `aggregate="median"` — взять медиану по sweep;
- `aggregate="none"` — сохранить все sweep внутри окна, используется для CNN.

Для `window_size=5` и `aggregate="mean"` объект имеет размер:

```text
501 признаков
```

Для `window_size=5` и `aggregate="none"` объект имеет размер:

```text
5 × 501 признаков
```

## Разделение train/validation

В проекте используется разделение по группам датасетов, а не случайное перемешивание отдельных окон. Это важно, потому что окна из одного измерения сильно похожи друг на друга.

Если перемешать окна случайно, часть почти одинаковых объектов может попасть и в train, и в validation. Это приведет к утечке и завышенным метрикам.

Используемая логика:

- валидационные группы выбираются на уровне `sample_group_name`;
- для AM берется `1` группа на validation;
- для FM берутся `2` группы на validation;
- для Noise берется `1` группа на validation;
- `RANDOM_STATE = 42`.

## Baseline на статистических признаках

Файл: `baseline_logreg.py`.

Что делает:

1. Загружает рабочий набор данных.
2. Добавляет относительную частоту.
3. Делит sweep на окна по `5`.
4. Считает математические статистики амплитуды.
5. Считает признаки формы спектра.
6. Делит данные на train/validation по группам.
7. Обучает несколько моделей.
8. Выводит метрики и матрицы ошибок.

Запуск:

```powershell
python baseline_logreg.py
```

Модели:

- `Logistic Regression`;
- `Random Forest`;
- `Gradient Boosting`;
- `MLPClassifier` на engineered features.

Основные группы признаков:

- базовые статистики амплитуды: `mean`, `std`, `var`, `median`, `min`, `max`, `range`, `iqr`, `skew`, `rms`;
- shape-признаки: центр масс спектра, ширина, энтропия, число пиков, отношение центра к краям, сглаженная структура, остаточная компонента;
- признаки по частотным областям: центр, края, левая/правая половина.

Контрольные результаты для текущего рабочего набора и `RANDOM_STATE = 42`:

| Модель | Accuracy | Macro-F1 |
|---|---:|---:|
| Random Forest | 0.975 | 0.976 |
| Gradient Boosting | 0.925 | 0.923 |
| Logistic Regression | 0.900 | 0.907 |
| MLP на engineered features | 0.800 | 0.821 |

Значения могут немного изменяться при изменении разбиения, состава датасетов, параметров окна или random seed.

## MLP и Logistic Regression на спектральных векторах

Файл: `mlp_spectrum.py`.

В этом эксперименте модель получает не только общие статистики, а сам усредненный спектр:

```text
501 амплитудная точка
```

Также реализовано расширение через multi-scale binning: спектр разбивается на блоки по `5`, `10`, `25`, `50` точек, после чего по блокам считаются агрегаты.

Запуск:

```powershell
python mlp_spectrum.py
```

Сравниваемые представления:

- `raw_501` — только исходные 501 амплитудная точка;
- `raw_501_plus_bin_mean` — 501 точка + средние по частотным блокам;
- `raw_501_plus_bin_stats` — 501 точка + набор статистик по блокам.

Контрольные результаты после очистки датасетов:

| Представление | Модель | Accuracy | Macro-F1 |
|---|---|---:|---:|
| `raw_501` | Logistic Regression | 0.900 | 0.900 |
| `raw_501_plus_bin_mean` | Logistic Regression | 0.900 | 0.900 |
| `raw_501_plus_bin_stats` | MLP | 0.825 | 0.840 |
| `raw_501` | MLP | 0.725 | 0.742 |

Вывод: простая MLP на текущем объеме данных уступает лучшим классическим моделям, но binned-признаки заметно улучшают результат относительно сырого спектрального вектора.

## 1D CNN

Файл: `cnn_spectrum.py`.

Входная форма:

```text
N × window_size × 501
```

При `window_size=5`:

```text
N × 5 × 501
```

В этой архитектуре sweep рассматриваются как каналы, а свертка идет вдоль частотной оси. Это ближе к анализу спектральной формы, чем MLP, но все еще не является полноценной 2D-обработкой матрицы sweep × frequency.

Запуск:

```powershell
python cnn_spectrum.py
```

Если PyTorch не установлен, скрипт завершится с сообщением о необходимости установить `torch`.

## 2D CNN

Файл: `cnn2d_spectrum.py`.

Входная форма:

```text
N × 1 × window_size × 501
```

При `window_size=5`:

```text
N × 1 × 5 × 501
```

Здесь каждый объект рассматривается как двумерная матрица:

- одна ось — временные sweep;
- другая ось — частотные точки;
- значение в ячейке — нормированная амплитуда.

Это позволяет модели анализировать локальную форму спектра и ее устойчивость во времени.

Запуск:

```powershell
python cnn2d_spectrum.py
```

Аугментации в `cnn2d_spectrum.py`:

- случайный сдвиг спектра по частотной оси;
- маскирование/обрезка левого края;
- маскирование/обрезка правого края;
- маскирование с двух сторон;
- небольшой гауссов шум.

Контрольный результат 2D CNN:

```text
accuracy: 0.97
macro avg F1-score: 0.97
```

Матрица ошибок:

|  | pred_AM | pred_FM | pred_Noise |
|---|---:|---:|---:|
| true_AM | 10 | 0 | 0 |
| true_FM | 0 | 20 | 0 |
| true_Noise | 0 | 1 | 9 |

Интерпретация: модель корректно классифицировала все AM- и FM-примеры. Единственная ошибка — один шумовой пример был отнесен к FM. Это подтверждает, что 2D CNN умеет выделять форму спектра, но шумовые участки с FM-подобными фрагментами остаются наиболее рискованным случаем.

## Важные проектные решения

### Почему используется относительная частота

Абсолютная центральная частота может стать нежелательной подсказкой для модели. Поэтому частоты переводятся в относительную шкалу:

```text
relative_frequency_hz = frequency_hz - center_frequency_hz
```

Так модель больше ориентируется на форму спектра, а не на то, на какой частоте был записан конкретный датасет.

### Почему используется окно из 5 sweep

Один sweep может быть шумным и нестабильным. Усреднение нескольких sweep снижает случайные колебания амплитуды.

Слишком большое окно уменьшает число обучающих примеров. Поэтому `5` sweep выбраны как компромисс:

- шумы уже частично сглаживаются;
- форма AM и FM становится стабильнее;
- число примеров остается достаточным для обучения.

### Почему validation делается по группам

Внутри одного датасета соседние sweep сильно связаны. Если случайно перемешать окна, модель может увидеть почти такие же примеры в train и validation.

Поэтому корректнее проверять модель на целых группах измерений, которые не попадали в обучение.

### Почему нужны разные модели

Классические модели полезны как baseline:

- быстро обучаются;
- хорошо работают на малом объеме данных;
- проще интерпретируются;
- показывают, насколько информативны вручную построенные признаки.

Нейросетевые модели полезны как проверка идеи:

- MLP проверяет качество векторного представления спектра;
- 1D CNN проверяет локальную структуру вдоль частоты;
- 2D CNN проверяет полноценную структуру sweep × frequency.

## Текущий вывод по экспериментам

После очистки сомнительных измерений задача классификации стала хорошо решаемой. AM отделяется наиболее уверенно за счет выраженной спектральной структуры. FM и Noise ближе друг к другу, поэтому для них важны признаки формы спектра и устойчивость этой формы после усреднения нескольких sweep.

Лучшие результаты показали:

- `Random Forest` на расширенных статистических и shape-признаках;
- `2D CNN` на матричном представлении `5 × 501`.

Это означает, что для текущего объема данных эффективны оба подхода:

- классический ML дает сильный и устойчивый baseline;
- 2D CNN подтверждает, что форма спектра может изучаться напрямую без ручного проектирования большого числа признаков.

Для дальнейшего развития проекта наиболее полезно расширять набор реальных измерений, добавлять новые типы сигналов и проверять устойчивость моделей на данных, собранных в других условиях.
