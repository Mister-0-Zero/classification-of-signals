# SignalScope

Desktop приложение для сканирования спектра и сбора данных. Версия 0.1
работает полностью в режиме имитации, без анализатора и обученных моделей.
Существующие исследовательские скрипты и датасеты проекта не изменяются.

## Запуск portable версии

Распакуйте весь архив в доступную для записи папку и запустите
`SignalScope.exe`. Каталог `_internal` должен оставаться рядом с EXE.
Python, PyVISA и драйверы анализатора для имитации не нужны.

1. Откройте «Подключение», выберите «Имитация», нажмите «Подключить».
2. Вернитесь в «Сканер» и запустите однократный проход 87–108 МГц.
3. Сравните «Только обзор» и «Обзор с уточнением».
4. Во вкладке «Сбор данных» выберите сцену, метки, параметры и запишите серию.

Пользовательские данные portable версии хранятся в `workspace/` рядом с EXE.
Если каталог с EXE доступен только для чтения, задайте доступную папку через
переменную `SIGNAL_SCANNER_HOME` перед запуском. Папка самих измерений также
выбирается в приложении. Для переноса программы копируйте всю portable папку.

## Реализовано

- Диапазон, три профиля и ручные настройки span/RBW/VBW/точек/детектора.
- Однократный и непрерывный проход, перекрытие окон, пауза и остановка.
- Обзор или обзор с дополнительными узкими измерениями кандидатов.
- Панорама текущего прохода, отдельный спектр, таблица находок и экспорт CSV.
- Состояния «Обнаружен», «Ожидает проверки», «Ранее обнаружен».
- Сбор с настройками формы или считыванием имитированной передней панели.
- Сцены: эфир, пустое окно, один AM, один FM, несколько, слабый сигнал.
- Операторские метки, комментарии, временные срезы, варианты RBW/VBW.
- Восстановление исходных настроек после завершения, остановки или ошибки.
- Настраиваемое сохранение сканирования; обязательное сохранение сбора.
- Встроенная справка и сохранение пользовательских настроек.

## Границы версии

Детектор — простой порог над оценкой фона. Определение модуляции не реализовано:
в таблице всегда «Неизвестно». Метка при сборе задаётся оператором и не является
результатом модели. Синтетические формы лишь демонстрируют сценарии и не
заменяют физический симулятор, реальные записи или валидацию алгоритмов.

TCP/PyVISA показаны в настройках, но сетевые обращения заблокированы.
Возврат локального управления реальным FSL3 пока не проверен и не реализован.
Скорость имитации не является оценкой скорости сканирования настоящим прибором.
Измерение энергопотребления и обучение контроллера также не реализованы.

Варианты сбора пока меняют только RBW/VBW (3/3 и 10/3 кГц), не span.
Разметка их метаданных имеет `labels_need_review=true`; все варианты связаны
общим `group_id`. Разметка частотных границ сигналов будет добавлена отдельно.

## Сохранение

Все измерения этой версии находятся под `simulation/` и помечены `simulated`.
Это предотвращает их неявное смешение с реальным `data/` исследования.

```text
simulation/
├── scans/<session>/
│   ├── session.json       # План, алгоритм, результат, время, покрытие
│   ├── events.jsonl       # Если включён журнал
│   ├── findings.json      # Если включён журнал
│   ├── samples/*.csv      # Только если включена запись спектров
│   └── settings/*.json
└── captures/<session>/
    ├── session.json
    ├── samples/*.csv      # Все частотные точки всех срезов
    ├── settings/*.json    # Фактические настройки каждой записи
    └── labels/*.json      # Метки, group_id, признак варианта
```

`class_name=UNLABELED` в CSV намеренно: операторские метки хранятся в JSON.
Среднее на графиках — арифметическое среднее уровней в dBm, не средняя мощность.

## Запуск из исходников

Python 3.11+, отдельное окружение приложения:

```powershell
python -m venv .local/desktop_env
.local/desktop_env/Scripts/python.exe -m pip install -r desktop/requirements.txt
.local/desktop_env/Scripts/python.exe desktop/run.py
```

Из исходников настройки по умолчанию хранятся в `.local/scanner_workspace/`
проекта; `SIGNAL_SCANNER_HOME` переопределяет этот путь.

## Проверки и сборка

Из папки `desktop/`:

```powershell
../.local/desktop_env/Scripts/python.exe -m unittest discover -s tests -v
$env:SIGNAL_SCANNER_HOME = "$PWD/build/smoke"
../.local/desktop_env/Scripts/python.exe run.py --smoke-test
```

Проверка UI создаёт синтетические записи, PNG экранов и `smoke_report.json`,
автоматически закрывает окно. Не направляйте её в рабочую папку измерений.

Для Windows-сборки из корня проекта:

```powershell
.local/desktop_env/Scripts/python.exe -m pip install -r desktop/requirements-build.txt
./desktop/build_windows.ps1 -Python "$PWD/.local/desktop_env/Scripts/python.exe"
```

Результат: `desktop/dist/SignalScope/SignalScope.exe`. Linux потребует
отдельной сборки и проверки на Linux; Windows EXE там не используется.

## Структура

- `domain.py` — типы, ограничения и план окон.
- `instruments.py` — интерфейс анализатора и синтетический адаптер.
- `detection.py` — заменяемый детектор; истинные классы симулятора не передаются в результаты.
- `services.py` — сканирование, сбор, пауза/отмена, регистрация находок.
- `storage.py` — файлы и настройки.
- `gui.py`, `plot.py` — Qt интерфейс, отдельный рабочий поток и графики.
- `smoke.py`, `tests/` — проверки интерфейса и основных сценариев.
