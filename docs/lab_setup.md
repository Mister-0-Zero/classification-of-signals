ветка main, исходный коммит 469c7b4. Доработки локальные, без commit/push.

## Запуск

На этом ПК создано отдельное окружение .local/desktop_env с Python 3.12.14.
Установлены PySide6-Essentials 6.12.0, PyVISA 1.16.2 и PyVISA-py 0.8.1.
Системный Python, VISA runtime и драйверы не менялись. Ранее Ethernet получил
192.168.10.1/24 без шлюза. VPN может перехватывать маршрут к прибору; текущая
доработка не меняет VPN, маршруты, firewall или сетевые интерфейсы.

Дважды щёлкните desktop/start_windows.cmd. Откроется версия из исходников.
Прежний EXE 0.1 не содержит LAN-адаптера; новая portable-сборка не создавалась.

Для воспроизведения окружения после установки совместимого Python:

~~~powershell
python -m venv .local/desktop_env
.local/desktop_env/Scripts/python.exe -m pip install -r desktop/requirements.txt -r desktop/requirements-lan.txt
.local/desktop_env/Scripts/python.exe desktop/run.py
~~~

## Первый аппаратный тест: только чтение

Выполняется с оператором после согласования готовности прибора.

1. Откройте «Подключение».
2. Выберите «PyVISA». Это чистый Python backend @py и VXI-11 через LAN.
3. Введите текущий IP прибора или TCPIP0::<IP>::inst0::INSTR.
4. Нажмите «Подключить». Приложение читает *IDN? и настройки; reset/preset,
   *CLS, изменение частоты, полос, точек и запуска не выполняются.
5. Сверьте идентификацию, версию прошивки, центр/span, RBW/VBW и число точек.
   Убедитесь, что передняя панель снова доступна для ручной настройки.

Каждая операция закрывает VISA-сеанс после запроса возврата Local. Ошибка
возврата не скрывается. Отсутствие ошибки протокола пока не доказывает,
что передняя панель реально доступна: это обязательно проверить на приборе.
Не запускайте сканирование или запись до проверки чтения.

Вариант «PyVISA (системная VISA)» использует установленный VISA runtime,
если он есть. Он не устанавливается автоматически. VISA SOCKET не
принимается вместо VXI-11 INSTR.

Вариант «TCP-сокет» — экспериментальная диагностика чтения на IP:порт
(порт по умолчанию 5025, фактическую доступность надо проверить). Сбор,
предпросмотр и сканирование через него заблокированы: механизм возврата
Local для raw TCP пока не подтверждён. Закрытие сокета не объявляется
подтверждением Local. При необходимости оператор использует кнопку Local.

## Минимальная запись

После успешного чтения и проверки ручного управления:

1. На анализаторе установите обычный Spectrum Analyzer, ненулевой span,
   линейную частотную ось, логарифмические единицы (dBm, dBµV, dBmV, dBµA, dBpW),
   обновляемую Trace 1 и Free Run trigger. Clear/Write допускает Sweep Count 0/1
   и больше. Для Max/Min Hold, Average и RMS нужен Sweep Count не меньше 1. Отключите gated sweep, Signal Track, Trace Math,
   APD/CCDF. Spectrum Emission Mask и Spurious Emissions не поддерживаются.
2. В «Сбор данных» выберите «Считать ручные настройки».
3. Задайте операторские метки, источник и комментарий. Для сомнительной
   модуляции используйте «Неизвестно».
4. Для повторов одного исходного наблюдения указывайте одинаковую «Группу
   наблюдения». При пустом поле каждое нажатие создаёт новую группу.
5. Для первого теста выберите 2–3 среза, дополнительные варианты выключите.
6. Нажмите «Записать» или Enter. Во время записи прибор выполняет свежие
   sweep; Trace 1 обновляется. INIT:CONT временно выключается, формат передачи
   временно ASCII. Их значения читаются заранее и восстанавливаются с проверкой.
7. Сверьте CSV/JSON, фактические настройки, число срезов и точек, частотные
   границы и доступность ручной настройки после записи.

Запись не меняет частоту, полосы, число точек, детектор, аттенюацию и
уровень отсчёта в ручном сценарии без вариантов. Для каждого временного
среза выполняется INIT:IMM;*OPC?, затем ASCII-экспорт Trace 1 во временный
уникальный файл прибора, чтение MMEM:DATA? и удаление этого файла. Частоты,
единицы и x-Axis берутся из файла. Max/Min Hold и Average начинают накопление
заново при INIT (руководство 6.143); прежняя история накопления не сохраняется.
Sweep Count 5 означает пять аппаратных проходов на один сохранённый срез.
Сохраняются отметки времени завершения и время ожидания/передачи. Таймаут
подбирается по Sweep Time × Sweep Count; последовательности дольше 300 с отклоняются. Остановка проверяется между
обменами; текущий обмен может ждать до таймаута.

Сначала проверьте одну короткую запись, затем запись после изменения
параметра и запись с неизвестной модуляцией. Только после этого переходите
к пробным широким окнам 1–2 МГц и сериям.

## Настройки формы и варианты

«Настройки из приложения» явно применяет частоту/span/RBW/VBW/точки/детектор,
затем считывает фактически установленные значения. Требования к режиму,
единицам и трассе сохраняются. Состояние существенных настроек и auto-флаги
считываются до операции и восстанавливаются после неё, остановки или ошибки.

Флажок дополнительных вариантов явно разрешает варианты RBW/VBW 3/3 и
10/3 кГц. Сначала сохраняется основная запись. У вариантов общая группа,
разные run_id/variant_id; метки вариантов требуют проверки.
Изменение span среди дополнительных вариантов пока не реализовано:
при необходимости меняйте span вручную, сохраняя общую группу наблюдения.

Восстанавливаются параметры, не история накопленных трасс и не точная
временная фаза непрерывного sweep. При обрыве связи восстановление нельзя
гарантировать: проверяйте сохранённые cleanup_errors и сам прибор.
Уже завершённые записи сохраняются при сбое следующего варианта.
Незавершённая серия срезов не выдаётся за успешную запись.

## Файлы и достоверность

Папка выбирается в интерфейсе. По умолчанию это
.local/scanner_workspace/data внутри проекта.

- simulation/captures/... — имитация, simulated=true.
- measurements/captures/... — путь адаптера прибора, simulated=false.
- samples/*.csv — все частотные точки всех завершённых срезов записи.
- settings/*.json — фактические параметры, raw SCPI-ответы, IDN, адрес/backend,
  отметки времени, время sweep/передачи, признак hardware_validated (протокольная проверка конкретной записи, не RF-калибровка).
- labels/*.json — метки оператора, session_id, observation_id/group_id,
  run_id/variant_id, signals=[], localization_status=unannotated.
- session.json — итог complete/stopped/error и диагностика.

Список границ сигналов пока пустой: метка «один/несколько» не является
разметкой локализации. Для повторов одной станции используйте одну группу,
в том числе при смещённом центре анализатора. Если известны частота станции
или параметры генератора, укажите их в источнике/комментарии.
График показывает арифметическое среднее логарифмических уровней в фактической
единице прибора; это визуализация, не оценка средней физической мощности.
Сырые срезы сохраняются отдельно. Для AUTOPEAK обе колонки сохраняются: основной
уровень и amplitude_min_<unit>. CSV dBµV содержит amplitude_dbuv, не amplitude_dbm.

Запрос DISP:TRAC1:X:SPAC? на FW 2.50 давал timeout и больше не вызывается.
Ось читается как явный столбец Hz в экспортированном файле FSL и сверяется
со start/stop/points. Неподтверждённая шкала не подменяется LIN. Проверяются
согласованность start/stop/center/span, длины массивов и конечность чисел.
Молчаливая обрезка исключена. Неподдерживаемые режимы и ответы отклоняются.
Основная разметка — утверждение оператора; варианты помечены needs_review.
Автоматический классификатор не подключён, в находках модуляция неизвестна.

## Основания для реализации и открытые вопросы

Официальное [руководство FSL, версия 12, FW 2.00](https://scdn.rohde-schwarz.com/ur/pws/dl_downloads/dl_common_library/dl_manuals/dl_user_manual/FSL_OperatingManual_en_12.pdf):
разделы 5.26–5.28 (LAN/VXI-11 и Go to Local), 6.7 (*IDN?),
6.130–6.135 (трасса, ось и формат), 6.143–6.149 (INIT и режим прибора),
6.180 (детектор), 6.223–6.228 (sweep), 6.256–6.257 (TRAC),
6.272 и 6.276 (триггер и единицы).

[PyVISA TCPIPInstrument.control_ren](https://pyvisa.readthedocs.io/en/latest/api/resources.html)
описывает интерфейсный возврат Local. В установленном pyvisa-py 0.8.1
TCPIPInstrVxi11 не переопределяет gpib_control_ren; базовый метод возвращает
error_nonsupported_operation. Поэтому только для этой закреплённой версии
адаптер использует изолированный вызов уже реализованного VXI-11
device_local и проверяет код ответа. Установленная библиотека не изменяется.
Другие версии при неподдержанной операции явно завершаются ошибкой.
Новый код pyvisa-py может отличаться от установленного релиза.

На приборе ещё нужно подтвердить: фактическую прошивку и поддержку запросов,
отсутствие изменения ручных настроек при подключении, механизм Local,
свежесть срезов, реальные времена обмена и восстановление после остановки/сбоя.
Старого data/ и dataset_inventory.csv в этом checkout нет.


## Автоматизированная первая аппаратная проверка

Из папки desktop выполнить:

~~~powershell
../.local/desktop_env/Scripts/python.exe -m signal_scanner.fsl_check --address 192.168.10.24 --capture 3 --wait 180
~~~

Проверка ждёт доступности указанного LAN-хоста, читает IDN и каждую команду
в отдельном сеансе. При неподдерживаемых командах сохраняет точную диагностику
и не запускает сбор. При успешной диагностике получает три трассы, проверяет
восстановление настроек и сохраняет их с purpose=hardware_validation,
training_eligible=false, без выдуманных меток оператора.
Результат: .local/scanner_workspace/data/fsl_check_latest.json.
Само наличие нового адаптера и прохождение offline-тестов не подтверждает
аппаратную совместимость; её подтверждает фактический отчёт и файлы измерений.

## Снимок и случайная серия

Текущая задача — наличие сигнала (нет/один/несколько), без модуляции. Кнопка
«Сделать снимок» всегда читает ручные настройки. При включённой серии: исходный
снимок, 10–20 случайных вариантов (по умолчанию 15), повтор исходного снимка.
Центр, span и число точек фиксированы; команды их изменения в этой серии
не отправляются даже при восстановлении. Поля настроек — только чтение.

План: RBW 0.002–0.2 span, VBW 0.1–1 RBW. Выбор без повторов из нормальных
ступеней 1/3 по декадам (RBW 10 Гц–10 МГц, VBW 1 Гц–10 МГц), с равномерным
охватом логарифмической шкалы. Filter Type должен быть Normal; FFT и каналные
фильтры автоматически не переключаются. Trace WRIT/AVER/MAXH и детектор
POS/RMS/SAMPLE варьируются отдельно. Sweep Count берётся исходный, а если он
0 — для AVER/MAXH временно 5. Sweep Time вариантов — AUTO.

В session.json сохраняются seed, полный план, исходное состояние и результат
восстановления. В каждом settings/*.json — фактические параметры, роль
baseline_start/random_variant/baseline_end и время установки/сбора. Метка
наличия относится к физическому сигналу в фиксированном окне, не к его видимости
после сглаживания. Варианты требуют проверки. Вся серия остаётся одной группой
при разделении обучающих и проверочных данных. quality_score пока null: качество
нельзя подменять одной уверенностью модели. Нужна проверка правильности
ответов на независимых наблюдениях и компромисс со временем.

Технический прогон без выдуманных меток:
~~~powershell
../.local/desktop_env/Scripts/python.exe -m signal_scanner.series_check --wait 300
~~~
Его signal_count=unknown, signal_present=null, training_eligible=false.
Отчёт: .local/scanner_workspace/data/series_check_latest.json. Поддержка генератора
и остановки в симуляторе не означает физическую модель эффектов Trace/детектора.

Аппаратная проверка новой серии завершена: 14.11.2026, FSL-3 FW2.50,
12/12 снимков (исходный+10 вариантов+повтор), 21.18 с. Во всех центр297 МГц,
span10 МГц, 1001 точка. Успешно применены WRIT/AVER/MAXH, POS/RMS/SAMPLE,
RBW30кГц–1МГц и VBW3кГц–300кГц; исходные параметры восстановлены.
Это проверенные сочетания данного прогона, не гарантия всех режимов/обрывов.
Источник данных указан в series_check_latest.json.
